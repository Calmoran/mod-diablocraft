# Difficulty tiers

`dc_tier_phase` maps the ten launch tier names to IDs/phases 1..10. Multiplier data stays in the generated `dc_difficulty_tiers` and `dc_party_scaling` tables. Percent values are divided by 100 exactly once. `dc_character_tier` persists the character's current choice. Master checks the account for level 60; Torment Iâ€“VI check the choosing character for level 60. Party members inherit their leader's choice on joining. Online party members must all be out of combat and outside instances before a selection moves them.

Tier data loads before world objects. The existing `OnBeforeWorldObjectSetPhaseMask` hook selects literal equality for launch phases. `PlayerPhase` decides a player's phase: in the Sanctum (map 750, the hub) the one shared phase `DC::World::SanctumPhase` for every tier, with one copy of every hub object and NPC; in the open world, outside instances, the selected tier's own phase. Picking a tier in the Sanctum changes the saved tier and no phase (03 §3). Instances retain their own phase/difficulty behavior. Game Master visibility/combat bypasses should be turned off when testing separation or engagement.

`TierBalance` implements the AutoBalance hook from patch 0003. AutoBalance supplies its normal/boss modifier defaults; Diablocraft multiplies these by the tier and party rows. Stock template/rank modifiers are already included in the captured creature baseline and are not applied twice. Dungeon and raid maps return false from this stage's opt-in hook. A future instance module can return true before creature level selection to own its scaling exclusively; AutoBalance then skips its dungeon stat, damage/healing, and crowd-control paths for that creature. Ownership is fixed until recreation. No rift system is implemented here.

Stock creatures using `npc_training_dummy` are excluded from scaling (approved by the designer). The Heroic Training Dummy's 24,009,944 baseline would otherwise exceed the Life ceiling at Torment VI with four players. Their database records remain stock. Every scaled creature is also checked against the core's safe health range before applying a multiplier.

An idle creature uses solo Life. The first player (or player-owned attacker) that engages it locks the count of that player's party members currently online in the same map and tier, up to the D3 four-player limit. Later attackers and membership changes do not alter that fight. The lock ends when combat ends. Phase/party transitions queue a refresh on the owning map thread; unchanged phase/count combinations are skipped. Combat entry applies its cached multiplier immediately, before subsequent hits. Calculations never run per hit.

`BypassCreatureMitigation` is the documented C8 policy interface for the future fixed-hit implementation in `02-combat`. A true result means bypass both armor and resistance for that target. This stage does not implement the hit path, elite promotion/affixes, XP/gold awards, or rifts.

The full-world copy approach is retired by `difficulty_0005_remove_full_world_copies.sql`. It removes only records identified by the old ownership tables, including related pools, events, formations and spawn groups. Stock placements and GM-created test spawns remain. Previous gathering-node removals remain archived in `dc_disabled_gathering_spawn`.

`data/d3/world_areas.csv` is the area allow-list (03 section 3 and 08 section 2, commit d3d984c). The CSV generator produces `dc_world_areas`; currently map 1 / area 876 (GM Island), all phases, is open. Approved patch 0004 provides an early default-allow spawn veto. `common/dc_world_areas.cpp` loads the rules before spawn systems, denies unlisted/closed open-world areas, and allows instance maps. Terrain and WMO area lookup uses the actual world position; a database areaId of zero never permits a spawn by itself. Missing/invalid rules fail closed and refuse login. The core patch contains no area or tier policy.

To open an area, regenerate/apply the allow-list SQL and restart, then run `dc areas scan <map> <area>` in the server console. This resolves stock phase-1 source positions with the core's area lookup and saves `dc_area_source`. Stop worldserver, run `python mod-diablocraft/scripts/generate/world/generate_area_copies.py --mysql <mysql.exe> --defaults-file <client.ini> --map <map> --area <area>`, apply the emitted `difficulty_area_<map>_<area>.sql`, and restart. The generated file is copied to the world updater directory; repeat runs overwrite the same name. Reapplying a changed generated migration requires explicit application and refreshing its updater hash. Existing copied GUIDs are reused, and unowned placements are preserved. Original source placements remain tier 1 at runtime; owned copies use tiers 2-10. This is the open world only: the Sanctum has no tier 2-10 copies (`world_0037`).

The generator checks source positions against the resolved snapshot, validates GUID ownership again before SQL mutation, and checks launch-tier Life with the largest open-world party. Stock rank/AutoBalance health modifiers are 1 in this installation; pass `--extra-health-multiplier` as a conservative bound if configuring larger modifiers. Supported placement data includes addons, movement overrides, multi-spawns, sparring, vehicle accessories, formations and linked respawns contained in the area. Event/pool/spawn-group membership, per-spawn SmartAI/conditions and fixed-GUID template targets currently stop generation with the affected row. Cross-area formation/respawn links also stop. No entire-map or pool-tree cloning occurs.

`dc areas audit` reports allowed/denied creation calls by kind (0 creature, 1 vehicle, 2 game object, 3 static transport, 4 moving transport, 5 pet). `dc areas test` checks all six policy kinds at open/closed/instance locations and four real early creation failures. It requires the initial GM Island-only policy. Actual pet-owner and transport-passenger gameplay remains a separate integration check when those systems are used.

For the GM Island-only world, set `Wintergrasp.Enable=2` in worldserver.conf: zero leaves its world processing active, including a portal setup that assumes its spawn succeeded. Disable continent boats with `IsContinentTransport.Enabled=0`; keep static transport preloading off. `difficulty_0007_disable_pvp.sql` uses the existing disable registry for all seven OutdoorPvP systems and all thirteen battleground/arena definitions, including aggregate queues. This core has no matching master conf switches. Disabled OutdoorPvP definitions produce misleading "no entry in database" startup messages; the controllers are skipped. Game-event and pool loaders already check failed creations. Their closed-area objects, world bosses, and the unconditional Deeprun Tram grid's objects are vetoed before initialization. Instances keep their existing behavior.

Use `scripts/build.ps1` for builds shared with Claude Code. It atomically acquires the repository-root `build.lock`, waits while a recent lock exists, refreshes its timestamp during a build, and removes only its own lock on completion/failure. A stale lock requires checking the owner first. MSBuild and compiler concurrency are both one (`-- -m:1 /p:CL_MPCount=1`); parallel builds exhausted memory with the server and MySQL running. Exact local settings are recorded in docs/install-dev.md.

`/dctier` opens the AIO screen. The client needs AIO_Client installed and enabled; fully restart WoW after first installing the addon. The server loads this screen from `lua/aio` through its configured ALE script path. It sends selection through the ordinary-player `dc tierselect` command; the same C++ validator handles every request. `.dc tier [1..10]` is the GM test command. With a creature selected, `.dc tier` prints its actual Life and writes a verification line to the server log.

Formula/unlock tests are in `scripts/tests/difficulty`. `test_spawn_migration.py` creates and removes its own isolated MySQL fixture database to check retirement of owned copies, preservation of stock/GM placements, and rerun safety.

Greater Rift levels (`dc_gr_scaling.h`, diablocraft-5o8y): in a Greater Rift `TierBalance` ignores the opener's tier and the open-world party row. Life is the base tier's (rifts tunable `gr_level_one_tier`, Hard) x `gr_life_per_level` per level above 1 x `1 + gr_party_life_pct_per_extra_member` per member beyond the first at the open; damage is the base tier's x the per-level number of each damage band, party damage unchanged. There is no Life ceiling: `ScaleCreatureLife` (`dc_tiers.h`) returns the true Life as a `uint64` (refused only at 2^64) and the multiplier AutoBalance turns into the core's 32-bit max, which is the Life itself up to 1,000,000,000 and exactly 1,000,000,000 above it, where `BigLife::Adopt` keeps the true Life in the pool (diablocraft-12in). Every Rift Guardian, Nephalem or Greater, multiplies the one rifts tunable `guardian_base_life` instead of its template Life. `GreaterRiftDamage(level)` gives elite affix damage the same factor. Tests: `scripts/tests/rifts/test_gr_scaling.py`.
